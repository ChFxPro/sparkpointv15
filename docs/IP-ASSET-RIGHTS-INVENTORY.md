# SparkPoint Asset Rights Inventory

**Prepared:** 2026-07-17  
**Scope:** Public-facing assets tracked in this repository, based on file names, code usage, repository history, and existing embedded metadata. This is an operational inventory, not a legal opinion and not evidence of ownership.

## How to use this record

For every asset family, save the underlying agreement, license, release, email permission, or source URL in the organization’s controlled records. Record the file name, source, grantor, date, scope (web, social, press, print), duration, credit requirement, territory, and any restrictions. Do not treat the presence of a file in this repository as proof that SparkPoint owns it or has all needed permissions.

## Repository and content posture observed

- No top-level `LICENSE`, `NOTICE`, or copyright notice file is tracked. `package.json` is marked `private`, which expresses package-publication intent but does not document copyright ownership or contributor terms.
- Site copy, code, structured data, and press copy are tracked, but the repository contains no contributor agreement, contractor assignment, asset-release register, or brand-use policy.
- Press workflow is a useful starting point: `docs/PRESS_PORTAL.md` requires accurate captions, credits when known, and usage notes, and the press generator carries those fields into media kits. It does not verify rights or require a credit/permission field.
- Optimized WebP/AVIF and copied public variants should be recorded as derivatives of their source asset, rather than treated as independently cleared assets.

## Priority evidence requests

1. Gather contractor/employee creation agreements and any historic design, photography, architectural-rendering, and web-development agreements.
2. Obtain a short written permission/release for each partner logo, co-branded initiative, event photo, testimonial, and identifiable-person image.
3. Resolve externally hosted Unsplash and Squarespace media first, because the repository does not preserve their clearance record.
4. Establish a controlled source-of-truth register (not a public repository if it contains releases or contact data) and link the asset family IDs above to that register.
5. Have counsel review the proposed SparkPoint trademark strategy, public copyright/trademark notice, repository license posture, and reusable release/contract language.
